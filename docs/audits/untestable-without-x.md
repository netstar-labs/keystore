# Untestable without X

Things this audit could not run, what each needs, and the exact command for a human to run.

| Needs | Why not here | Command |
|---|---|---|
| The real macOS login keychain via `/usr/bin/security` | the owner has not confirmed writes to their keychain; a `keystore` item may already exist and is not to be touched. The test is written, double-gated, and **unexecuted**. It uses a unique service `keystore-l3-throwaway-<rand>` (never `keystore`), deletes it in `t.Cleanup`, and macOS may show an access prompt | `cd keystore && GOWORK=off KEYSTORE_LIVE=1 KEYSTORE_LIVE_KEYCHAIN=1 go test -tags integration -count=1 -v ./integration/keychain/` |
| `keystore keychain-set` interactively (security prompts on the terminal) | needs a human at a terminal | `keystore keychain-set -service my-test-svc` (type the ring's passphrase), then `echo hi \| KEYSTORE_KEYCHAIN=my-test-svc keystore sign -keystore RING` (sign resolves the passphrase through the keychain; `list` does not unlock and would prove nothing); remove with `security delete-generic-password -s my-test-svc -a keystore` |
| Whether the keychain test's environment is enough (**untried**) | `livetest.Run` gives child processes a temp `HOME`, and `security` may then not find the login keychain; the keychain test passes the real `HOME` to the end-to-end `sign` for that reason, but it has never run | read the first failure of the command in the first row |
| A second real uid on macOS (LOCAL_PEERCRED across users) | needs another login or `sudo -u` user | as user A: `keystore-agent -keystore R -sock /tmp/a/s -passfile P` in a 0700 dir; as root: `sudo keystore sign -agent /tmp/a/s -in msg` must say "served by uid" |
| systemd on a real host (**untried**: neither `systemd-analyze` nor `systemctl` was run here) | the containers have no init | `examples/agent-service/keystore-agent.service` copied to a host: `systemd-analyze verify keystore-agent.service`, then `systemctl start` and a `keystore sign -agent` |
| launchd (**untried**: `plutil -lint` is run by `examples/agent-service/run.sh` on macOS only, and nothing was loaded) | not loaded on purpose | `plutil -lint examples/agent-service/local.keystore-agent.plist`; load under a throwaway label with `launchctl bootstrap gui/$(id -u) FILE` |
| Linux `-race` | static build has cgo off; `-race` needs a C toolchain on linux | on a Linux host: `go test -race -count=1 ./...` |
| linux/amd64 | only arm64 was run | `GOOS=linux GOARCH=amd64 go vet ./...` (cheap) and the suite on an amd64 host |
| OpenSSL other than 3.5.x, or LibreSSL 3.7+ | only 3.5.7 and 3.5.9 were available | `KEYSTORE_LIVE=1 go test -tags integration -count=1 -v ./integration/interop/` on that machine (skips if no Ed25519) |
| Package mirrors offline | the Linux tier installs bash/openssl/setpriv at run time | rerun `integration/run.sh` with network; a skip says so |
| That `fsync` happens, and power-loss durability of a committed ring (format.md and scope property 3, "durable once the command returns") | atomicity (old or new, never torn) is tested, including by real `SIGKILL` (`TestSaveCrashSafety`, `TestCrashLoop`), but a killed process cannot lose the page cache, so no kill-based test can see a dropped `fsync`; the `hook` seam fires per stage, not per `fsync`. Mutants M106, M119, M121 (`ringfile`) and M338 (`output.go writeNew`) survive for this reason ([mutation-hardening.md](mutation-hardening.md)). A `var syncFile` seam would prove the call, not durability, and was not added. The `Sync` calls exist at `ringfile.go` (temp file and directory) and `output.go` (`writeNew`, `replace`), and Go's darwin `os.File.Sync` uses `F_FULLFSYNC`: asserted by reading the code (reported: Go source `internal/poll/fd_fsync_darwin.go`, audit A5 and A7), not by a test | pull the power on a real host mid-write and check the ring opens, or run the ring on a filesystem that records `fsync` calls (**untried**); `strace -f -e trace=fsync,fdatasync -- keystore add ...` on Linux shows the calls (**untried**) |
| macOS keychain error mapping | `internal/keychain.Get` returns `ErrNotFound` for any `security` failure (locked, denied, absent), so no test can distinguish them; the real `/usr/bin/security` is no longer run by the default suite (the old `TestGetMissing` asserted nothing and was removed, audit A7 G15) | the live test in the first row |
